# Livegram-style Relay Bot

A Telegram bot that works like @LivegramBot: users message the bot, their
messages get relayed to you (the admin), and when you reply to a relayed
message, the bot delivers your reply back to that exact user — plus
blocking, canned quick replies, history, stats, away-mode, and optional
AI auto-chat.

## How the relay works

- Any message a normal user sends is copied into your chat with the bot,
  with a header showing the sender's name/id and quick-reply buttons
  attached.
- Reply (Telegram "reply", not a new message) to that copied message, and
  the bot forwards your reply back to the original sender.

## Features

| Command | Who | Description |
|---|---|---|
| `/start` | everyone | Greeting |
| `/help` | everyone | How to use |
| `/users` | admin | Count of known users |
| `/stats` | admin | Users, messages today/total, AI & away status |
| `/block <id>` | admin | Block a user (or reply to their relayed message) |
| `/unblock <id>` | admin | Unblock a user |
| `/history <id>` | admin | Last 20 messages with a user (or reply) |
| `/addcanned Label \| Text` | admin | Add a quick-reply button |
| `/cannedlist` | admin | List canned replies with their ids |
| `/delcanned <id>` | admin | Remove a canned reply |
| `/away <text>` / `/away off` | admin | Auto-reply to users while you're away |
| `/ai on` / `/ai off` | admin | Toggle AI auto-chat |
| `/broadcast <text>` | admin | Message every known (non-blocked) user |

Quick-reply buttons and a **🚫 Block** button appear under every relayed
message automatically — tap a canned reply to send it instantly, or tap
Block to cut a user off without typing a command.

### Away mode vs. AI mode

If both are off, users just get "✅ Sent, you'll hear back here" and wait
for you. If **away mode** is on, they get your away message instead
(throttled to once per 30 minutes per user, so it's not spammy). If **AI
mode** is on, it takes priority over away mode and Claude answers using
the last few messages in that user's history for context — you can still
jump in and reply manually at any time.

## 1. Create the bot

1. Talk to [@BotFather](https://t.me/BotFather) on Telegram.
2. `/newbot`, follow the prompts, and copy the token it gives you.
3. Get your own numeric Telegram user id from [@userinfobot](https://t.me/userinfobot).

## 2. Local test (optional)

```bash
pip install -r requirements.txt
export BOT_TOKEN="123456:ABC-your-token"
export ADMIN_ID="123456789"
python bot.py
```

Without `WEBHOOK_URL` set, the bot runs in polling mode — good for local
testing.

## 3. Deploy on Render

1. Push this folder to a GitHub repo.
2. On [Render](https://render.com), click **New +** → **Web Service**, and
   connect that repo. Render will detect `render.yaml` automatically
   (or set Build Command `pip install -r requirements.txt` and Start
   Command `python bot.py` manually).
3. In the service's **Environment** tab, add:
   - `BOT_TOKEN` — the token from BotFather
   - `ADMIN_ID` — your numeric Telegram id
   - `WEBHOOK_URL` — your Render service URL, e.g.
     `https://livegram-bot.onrender.com` (find this on the service page
     after the first deploy)
   - `ANTHROPIC_API_KEY` — only needed if you want `/ai on` to work; get
     one from [console.anthropic.com](https://console.anthropic.com)
   - `AI_MODEL` (optional) — defaults to `claude-sonnet-4-5`
   - `AI_SYSTEM_PROMPT` (optional) — customize how the AI represents you
4. Deploy. On startup the bot registers its webhook with Telegram
   automatically — no manual `setWebhook` call needed.
5. Message your bot on Telegram — it should relay to you, and your replies
   (or canned buttons, or AI) should relay back.

### Note on the free plan

Render's free web services use **ephemeral disk** — the SQLite file in
`data/bot.db` (users, message history, canned replies, settings) will
reset on redeploys or if the instance restarts after idling. That's fine
for testing; for persistent data in production, swap `storage.py` for a
managed database (e.g. Render's free Postgres tier) or attach a Render
persistent disk.

### A note on AI mode

When AI mode is on, replies are generated by the Claude API using each
user's recent message history as context — there's no guardrail beyond
the system prompt you configure, so review `AI_SYSTEM_PROMPT` and keep an
eye on `/history` for any user your AI is talking to unsupervised for a
while.
